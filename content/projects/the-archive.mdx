<Section id="brief" n="00" title="Brief">

A portfolio usually describes work. This one measures it. Underneath the editorial archive — the dossiers, the essays, the library — runs an ops layer that watches the same agent fleet the entries describe: sessions parsed from the transcripts Claude Code leaves on disk, git telemetry from the repos themselves, and the nightly gate results the fleet's own automation writes. The front door is a drawn San Francisco that keeps the city's real time and weather; the board under it is entirely measured.

The site maintains itself on a schedule. Every morning it files a sanitized fleet report and the deployed site serves that record, labeled with its cut time. Every day the library re-mirrors its source documents deterministically. Every Sunday a curator agent checks each entry against its source repo and publishes updates only through gates code enforces — a failed gate parks the work on a branch instead of shipping it.

And because the entries it curates are agents, the site is where the honesty rules live: every number traces to a source repo, states are labeled as inferred, and a report can never carry a prompt, a path, or a patch.

</Section>

Every session's tool calls are split three ways — **build** (edits to the agent's own source), **operate** (the agent running its actual job), **verify** (tests and checks) — using a committed, reviewed registry of each agent's operate and verify tokens. The honesty rule is enforced in copy: these agents persist no run output to disk, so operate counts are labeled as invocations counted from transcripts, never as products made.

The automations hold the loop while the operator sleeps:

<Section id="surfaces" n="02" title="The surfaces">

The reading layer is built to carry evidence, not vibes. Each dossier's console ports its repo's real rules and executes them in the browser on labeled, representative data — the citation-gate arithmetic in JIM's console is the same `max(2%, 0.05)` tolerance the repo enforces. Click-to-inspect opens verbatim excerpts from the source repos, keyed to topology nodes, with the provenance of every published number cited where it was measured.

The content model is a graph, not a folder: entries declare `refs:` in frontmatter, the build resolves them, computes backlinks, and assigns archive numbers chronologically. Adding a project to the site is one file with one `repo:` field — the same field the fleet roster, the curator, and the dossier's ops strip all read.

Scroll performance is doctrine, learned the hard way (below): no backdrop-filter anywhere, no SVG filter blur, soft bodies rendered as gradients, and the full city scene animates only on the front door — content pages hold a still frame.

</Section>

<Section id="decisions" n="04" title="Decisions & tradeoffs">

<Decision
  n="01"
  title="The deployed site serves a filed report, not live data"
  chose="Measurement runs only on the operator's machine; the public board renders the last sanitized snapshot, labeled with its cut time."
  over="A hosted collector, a database, and live polling in production."
  cost="The public board is up to a day old, and says so."
  payoff="No server to run, no credentials in production, and sanitization enforced at the cut — a report physically cannot carry prompts, repo paths, patches, or steering notes."
/>

<Decision
  n="02"
  title="Autonomous merges, deterministic counterweight"
  chose="The Sunday curator publishes fact updates to main on its own — but only if the content check, the production build, and a diff-scope allowlist all pass; anything else parks on a branch."
  over="Review-everything (drift accumulates) or trust-the-model (drift ships)."
  cost="A gate failure means updates wait for a human — freshness loses to safety."
  payoff="No drift → no model run → zero spend. The model writes; code decides what ships."
/>

<Decision
  n="03"
  title="The graph is computed, never curated by hand"
  chose="Archive numbers, cross-links, and backlinks are derived at build time from frontmatter refs; a content check gates every edit."
  over="Hand-maintained indexes and related-links sections."
  cost="A build step and a validator to keep honest."
  payoff="The archive grows by adding a file, and a dangling reference is a failed check, not a dead link."
/>
